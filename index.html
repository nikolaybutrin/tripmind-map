Под капотом
Как это работает — технологический разбор
Три инженерные опоры, граф мультиагентного пайплайна, бюджет латентности по этапам и почему гибрид точнее чистого LLM. Ни одна опора по отдельности не уникальна — уникальна связка под РФ-рынок.
01
Мультиагентная система + матоптимизация
LangGraph 1.0 · Google OR-Tools (TSP / VRP)
Закрывает риск «AI генерирует красиво, но непрактично». Порядок точек считает математика, а не LLM.
02
Travel Knowledge Graph
OWL2 · Apache Jena · Neo4j · Sherpa API · RAG
Закрывает риск «LLM врёт на фактах». Визы и медицина — из верифицированных источников, а не из памяти модели.
03
152-ФЗ-native архитектура
YandexGPT · GigaChat · Mistral self-hosted · Yandex Cloud УЗ-1
Закрывает регуляторный и санкционный риск. GPT-4o и Claude в РФ недоступны; ПД — только в российском контуре.
Опора 01 · оркестрация
⚙️ Граф мультиагентного пайплайна (LangGraph)
Один запрос проходит цепочку из шести узлов — на каждом работает свой оптимальный движок: LLM, алгоритм или API. Граф умеет ставиться на паузу для человека (HITL) и возвращаться назад при конфликте ограничений. Кликните узел, чтобы увидеть детали.

Опора 01 · производительность
⏱ Бюджет латентности по этапам

Опоры 01 + 02 · обоснование
🎯 Почему гибрид, а не «спросить у GPT»
Чистый LLM проваливается и на жёстких ограничениях (часы работы, окна, бюджет), и на фактах (визы). Поэтому LLM у нас — только «переводчик на человеческий», а решения принимают оптимизатор и верифицированные источники.

Опора 02 · факты
🕸 Travel Knowledge Graph — где живут визы и факты
Граф знаний хранит сущности (страны, города, POI, правила) и связи между ними. Jena «думает» по OWL2-правилам и выводит новые факты; Neo4j «отвечает» за миллисекунды на рантайме. Sherpa и RAG держат данные свежими; POI попадают в граф ingestion-пайплайном из Yandex Geosearch / OSM.
🔗 Фрагмент графа знаний
Запрос «культурные места с открытыми часами утром» решается обходом графа за миллисекунды — LLM не нужен.
🧠 Конвейер фактов
🧩
Apache Jena — «мозг, который думает»
OWL2-reasoner выводит новые факты из правил: «РФ + Турция ≤ 60 дн → виза не нужна». Никаких if-else в коде.
↓ материализация выведенных троек
⚡
Neo4j — «память, которая отвечает»
Property-graph с index-free adjacency: sub-millisecond обходы на рантайме обслуживают мультиагентную систему.
Sherpa API180–200+ стран, 200+ изменений виз/день, точность 97–99%. Фолбэк на кеш графа при недоступности.
RAGСвежие травел-объявления (МИД и т.п.) подмешиваются в контекст, если правила поменялись сегодня.
POI-ingestionPOI грузятся в граф из Yandex Geosearch (основной) + OSM/Overpass + Wikidata (заграница): batch по приоритетным направлениям + ленивая дозагрузка с кешем. Категории → travel-теги при загрузке. Матрица расстояний в граф не кладётся — живой вызов карт.
Опора 03 · 152-ФЗ-native
🔀 LLM-роутер — модель под задачу, без OpenAI/Anthropic
Не одна модель «на всё», а маршрутизация по типу задачи и нагрузке. Все провайдеры — в российском контуре (152-ФЗ). При падении или превышении квоты — fallback к соседней модели.
